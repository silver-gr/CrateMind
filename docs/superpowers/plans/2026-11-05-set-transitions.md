# CrateMind Set Transitions («Μίξη set») Implementation Plan

> **For agentic workers:** implement task-by-task, test-first, one fresh implementer per task and one batched reviewer per lane (see "Execution"). Steps use checkbox (`- [ ]`) syntax. Every implementer/reviewer brief MUST name the skills to load.

**Goal:** Give every adjacent pair of tracks in a DJ set an editable, previewable transition (preset + volume/EQ/filter/loop curves + length in bars + anchors), and play a set as one continuous mix on the two docked decks — the Spotify "Mix" feature (screencaps in `Spotify Mix Playlist/`, inventory in Appendix A) built on CrateMind's own engine.

**Architecture:**
- **Backend:** one new table `set_transitions` keyed by `(set_id, from_track_id, to_track_id)` (same idea as `TrackPairNote`, survives reorders), a pure resolver `services/set_transitions.py` that picks the «Αυτόματο» preset for a pair from BPM/key/profile, and three GET/POST/DELETE routes under `/api/sets/{id}/transitions`. Anchors (where the window sits in each track) are resolved on the frontend, which owns the real beat grid.
- **Audio core (frontend):** two additions inside `StretchDeck` — `playAt()` (sample-accurate scheduled start: the vendor worklet pre-rolls immediately, the `fade` gain holds silence until T0) and a per-deck **automation stage** (`node → fade → auto gain + 5 biquads → output`, driven with `setValueCurveAtTime` on the shared AudioContext clock, never touching the mixer's own EQ/filter/master params). No mixer lock: automation lives on its own nodes; a user's move during a transition is an override (DJ convention).
- **Conductor:** `lib/mix/*` plans a transition from the two decks' grids/cues, arms deck B at `T0 − 4 s`, and executes it on the AudioContext timeline; a headless `<MixConductor/>` in `AppShell` walks the set and shows a status strip above the dock.
- **UI:** a transition pill in the Set Builder connector row, a full-screen «Επεξεργασία μετάβασης» dialog (overview strip, dual zoomed waveform with bar grid and curve overlays, draggable N-bar window with single-pointer/keyboard alternatives, preset chips, parameter selects, preview, save), and «Αναπαραγωγή ως μίξη».

**Tech Stack:** FastAPI, SQLModel, SQLite, pytest (uv) / React 19, TypeScript, Vite 8, Tailwind v4, Radix (shadcn), motion/react, Web Audio + Signalsmith Stretch worklet, bun test, Tauri sidecar (PyInstaller).

**Spec:** this document (Appendix A = feature inventory from the screencaps; Appendix B = preset/curve/copy tables). Task 0 copies it to `docs/superpowers/plans/2026-11-05-set-transitions.md`.

## Decisions taken (2026-11-05; user: "use common sense and best practices", no detail questions, no confirmations)

1. **Integration point is the Set Builder** (`/sets`): the set is the playlist. Pill between rows, editor dialog, «Αναπαραγωγή ως μίξη» in the set header; playback on the docked decks; the conductor lives in the app shell and survives navigation.
2. **Per-set transitions keyed by ordered pair.** Same track twice in one set = both occurrences share one row (documented limitation). Orphans (pair no longer adjacent) ignored on read.
3. **No Effects row** (Spotify's "Effects: None"): CrateMind has no FX engine. Follow-up.
4. **No new audio engine, no beat analysis.** Grids come from djay import or the BPM/entry-cue estimate (+ user downbeat). Tracks that can't use the stretch engine (AIFF, > 400 MiB decoded, element fallback) get «χωρίς μίξη» and the **cut path**.
5. **Tempo:** incoming deck matches the outgoing deck's *grid* tempo at the anchors (octave-normalised), `rateIn = fold(outGridTempo·rateOut / inGridTempo)`; after the window it ramps back to its native tempo over 8 bars (timer wake-ups, progress from elapsed audio time) and its pitch range is restored. **One eligibility quantity on both sides:** the incoming playback rate `fold(from/to)`; `|rateIn − 1| > 0.16` → `tempo_match=0`, Auto picks «Κόψιμο». **Key lock is on for both decks during a session** and the user's values are restored on stop.
6. **No mixer lock.** Automation runs on a dedicated stage inside the deck; the mixer's own EQ/filter/faders stay downstream, so a user's move during a transition is **additive** (it does not cancel the automation; «Διακοπή» does). Documented in the README. At session start: crossfader centred if no MIDI controller is connected; a hint if a deck fader is at 0 or `|crossfader| > 0.05`.
6b. **Armed = playing.** `playAt` fires `play` at arm time (the pre-roll is real rendering, muted). The app treats an armed deck as playing (`deckIsPlaying(B)` true, keyboard ownership moves to B, `routePlay` never loads onto it); the strip shows «ετοιμασία…» until T0. Pinned by a test.
6c. **Auto identity contract:** a non-persisted row is `preset:"auto"` with `resolved_preset` (e.g. `"blend"`) and the resolved curves/bars; the pill shows «Αυτόματο · Ανάμειξη»; the editor selects the «Αυτόματο» chip and shows the resolved parameters. Saving with the Auto chip still selected stores `preset:"auto"` (anchors may be customised). Resolver → GET → pill is one tested chain.
7. **Single-pointer and keyboard alternatives** to every drag (WCAG 2.5.7): bar-length select, bar/beat nudge buttons for both the window and the incoming-track offset, arrow keys.
8. **Greek copy** everywhere (preset names translated; BPM/EQ/loop/cut/fade/crossfade/LP/HP/bar stay English).
9. **QA environment:** the user's web app (`:8000`/`:5173`, dataset root `…/gr.x3lixi.cratemind.preview`) stays up and is never touched. The user explicitly asked for a second environment on a copy of the data: it is built from the **newest verified backup bundle** (a consistent snapshot, `verify_backup`), never from the live WAL files, into a sibling root at `:8010`/`:5174`. Hermetic synthetic click tracks are added to that copy for the beat-accuracy check.
10. **Version:** minor (0.5.0) but the release is a separate step with the user's OK; this plan ends at a green branch + CHANGELOG «Unreleased». Note for the release: a library-exchange bundle from 0.5 is rejected by older installs (unknown table), by design of `schema_contract.py`.

## Review Focus

Failure modes the feature implies; each has a test in the task named.

1. **Key lock and pitch range after a session:** both decks had key lock off and deck B range 0.16 before «Αναπαραγωγή ως μίξη»; after «Διακοπή» (even mid-ramp-back) both are restored and B's rate ends at 1.0 (Tasks 7, 8).
2. **Deck B is not decoded in time:** readiness deadline = `min(T0 − 4 s, outEnd − 8 s)` in audio time; if B becomes ready after the deadline but before `outEnd − 2 s` → the cut path at `outEnd`; if B is still undecoded at `outEnd − 2 s` → the session stops with «Η μίξη σταμάτησε: το επόμενο track δεν φορτώθηκε» and A plays to its end (no mid-track silence, no double start); A's `ended` while stopping does nothing (Task 8).
3. **A reorder or removal in the Set Builder while a mix plays:** `notifyMixSetChanged` rebuilds the upcoming queue from the new order; if the playing track was removed the session stops cleanly (B not ejected, strip gone) (Tasks 8, 13).
4. **Near-octave or out-of-range BPM pairs:** 80 → 160 keeps tempo match at rate 1.0; 98 → 160 sets `tempo_match=0`, pill «Κόψιμο», plan has 1 bar and `rateIn=null` (Tasks 1, 7).
5. **The window dragged past either track's bounds:** clamps with rubber-band + spring back; `outStartS ≤ duration − windowS` always; backend rejects out-of-range anchors with 422 (Tasks 2, 7, 10).

**`frontend/src/lib/transitions/planner.ts`** (pure)
```ts
export interface LaneInput { trackId: number; grid: BeatGrid | null; duration: number; cues: TrackCue[]; rate: number; onEngine: boolean }
export interface TransitionPlan { kind: "mix" | "cut"; outStartS: number; outEndS: number /* source seconds */; inStartS: number; inEndS: number /* source seconds consumed by the incoming deck */; windowAudioS: number; bars: number; rateIn: number | null; rampBackBars: 8; loop: {start: number; end: number} | null; curves: CurveSet | null; reasons: string[] }
export function tempoMatchRate(outGridTempo: number, rateOut: number, inGridTempo: number): number | null   // fold(outGridTempo·rateOut / inGridTempo) into [0.7071,1.4142); null if |r−1| > 0.16 — the same quantity as the backend's tempo_match_rate
export function resolveAnchors(out: LaneInput, inn: LaneInput, params: TransitionParams): { outStartS: number; inStartS: number; bars: number; reasons: string[] }
export function planTransition(out: LaneInput, inn: LaneInput, params: TransitionParams): TransitionPlan
```
**Source time vs audio time.** Bars are counted on the outgoing track's grid in **source** seconds: `outEndS = timeAfterBars(out.grid, outStartS, bars)` (exact on irregular grids); `windowAudioS = (outEndS − outStartS) / out.rate`; the incoming deck consumes `inEndS = inStartS + windowAudioS · effectiveRateIn` source seconds where `effectiveRateIn = rateIn ?? 1` (the runner plays at `rateIn ?? 1`). Bounds: `outEndS ≤ out.duration` and `inEndS ≤ in.duration`; if a bound fails, `bars` is reduced (halving down to 1) and anchors re-resolved; if even 1 bar does not fit, `kind="cut"` (`reason "no_room"`). Anchor rules: out start = **last exit cue after the track midpoint** (`exit_cue`), else `snapToBar(out.duration − (outEndS−outStartS at the requested bars) − barSeconds, "down")`, then re-snapped down until `outEndS ≤ out.duration`; in start = **first entry cue** (`entry_cue`) else the first downbeat ≥ 0; both snapped to their grids; `grid_estimated` when either grid is `estimated`. **Missing grid** (`buildBeatGrid` returned null: no BPM): `kind="cut"`, `outEndS = out.duration`, `inStartS = first entry cue ?? 0`, reason `no_grid`. `kind="cut"` also for preset `none` and when either lane is `!onEngine`; a cut plan has `outStartS = outEndS` and `windowAudioS = 0`. `rateIn = tempoMatchRate(60/period(out.grid at outStartS), out.rate, 60/period(in.grid at inStartS))` when `tempo_match`, else null.

Abort before T0: pause `in`, neutralise both now; abort after T0: jump to the end state (pause `out`, neutralise `in` over 1 bar, keep its rate). Every callback is a wake-up: it re-reads `now()` and acts on audio time (a late completion wake-up still runs the completion). Completion (first wake-up with `now ≥ T1 + 0.25`): `out.pause()`, `outEngine.clearLoop()`, `inEngine.cancelAutomation("neutral")` immediately, `outEngine.cancelAutomation("neutral", now + 0.05)` (after the halt fade; no blip), owners null, resolve `"completed"`; then the ramp-back: wake-ups every 50 ms, `progress = (now − rampStart)/rampAudioS` clamped, `setDeckPitch(in, pitchAtArm·(1−progress))`, final `setDeckRangePitch(in, rangeBefore, 0)`. `dispose()` cancels timers, listeners, pending starts, automation (`"neutral"`), loops and the ramp; idempotent. **Cut kind, all four combinations, one cut timestamp `tCut`:** out engine + in engine → `tCut = outEngine.timeOf(outEndS)`; `inEngine.playAt(tCut, inStartS, 1)` and an owned `out.pause()` at a wake-up ≥ `tCut`; out engine + in element → `in.seekTo(inStartS)` at arm; at a wake-up ≥ `tCut = outEngine.timeOf(outEndS)`: `in.play()` then owned `out.pause()`; out element + in engine → listen to the out media's `timeupdate`/`ended`; when `position ≥ outEndS − (lead + 0.3)` (or `ended`, or the out media is already `ended` at arm): `tCut = now + lead + 0.05`, `inEngine.playAt(tCut, inStartS, 1)` and the owned `out.pause()` is scheduled for a wake-up ≥ `tCut` (never immediately: the engine is silent until its anchor, `stretchDeck.ts:364`, and an immediate pause would leave a ~210 ms gap); out element + in element → `in.seekTo(inStartS)` at arm; trigger at the same `outEndS − 0.3` boundary via `timeupdate` (not only `ended`), `in.play()` then owned `out.pause()`. Resolve `"cut"`. **Natural completion:** when `outEndS` is at (or within 0.5 s of) the out track's end, the engine's `finish()` emits `pause` then `ended` (`stretchDeck.ts:390`) before the completion wake-up; the runner recognises an unowned `pause` as expected completion when `now ≥ T1 − 0.05` or the out position ≥ `duration − 0.05`, and completes instead of aborting. **Seek ownership** persists until the matching `seeked` event (a counter of pending owned seeks, decremented on `seeked`; `seeking` while the counter > 0 is owned), because the setter defers both events (`stretchDeck.ts:173`). ## Known limitations (pinned in tests, shown in the docs)

- Same track twice in one set: both occurrences share one transition row.
- No effects row; `noise_out` is not offered.
- Element-fallback tracks (AIFF, > 400 MiB decoded, decode failure) are cut, not mixed.
- Phase alignment is only as good as the grid: estimated grids can be off by up to half a beat.
- The incoming deck's tempo ramp-back is a 50 ms main-thread ramp.
- A user's crossfader/EQ move during a transition overrides it (no lock).
- QA runs in Chromium (ego-browser); the desktop app uses WebKit.
