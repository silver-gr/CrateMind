# Repository Guidelines

Guidance for every coding agent working in this repository. Claude Code loads `AGENTS.md` itself when a project has no `CLAUDE.md`, so this is the only rules file: do not add a `CLAUDE.md` or `.claude/CLAUDE.md` beside it (other agents then ignore it and warn).

## What this is

CrateMind is a local-first, single-user DJ intelligence layer. It scans a music library, lets the user attach **taste metadata** (energy/intensity/darkness/set role/status/substyle/…), finds duplicates, builds sets with a transparent recommender, plays two decks with a djay-style mixer and a Numark Mixtrack Platinum FX controller, and exports artifacts (M3U8 / CSV / JSON backup / Markdown).

**Data-safety invariant (the product's reason for existing):** CrateMind owns *taste metadata only*. It must never delete, move, or retag source audio, and never touches beatgrids or cue points in DJ apps, and never writes to, moves or locks DJ-app files. An opt-in import may read them: the library database from a private copy, and per-track analysis files in place, read-only. Scans are read-only; exports write to the configured output dir, never the source library. Duplicate detection flags groups for review and never auto-deletes. Treat any task that implies mutating the music library as a bug unless the user explicitly asks. Tests and QA must never touch real user data (the live dataset or djay files).

## Runtimes

- **Web (development):** FastAPI backend on `:8000` plus the Vite frontend on `:5173` (proxies `/api`). Both must run together. The web backend answers only to its own hostnames and refuses writes whose `Origin` is foreign (`app/web_guard.py`; `CRATEMIND_ALLOWED_HOSTS` adds exact hostnames). The Vite `/api` proxy vouches for pages it serves by rewriting their `Origin` (`fronts` in `vite.config.ts`, `lib/devProxyOrigin.ts`).
- **Desktop:** Tauri 2 shell in `native/` with the backend frozen by PyInstaller as a sidecar (`backend/packaging/desktop.spec`, which bundles librosa/SciPy/numba for local BPM/key analysis; Essentia and provider jobs stay web-only). MIDI (the controller) is handled by the native shell and exists only in the desktop app. macOS preview build: see `docs/TAURI_DESKTOP_OPERATIONS.md`. An unsigned Windows x64 one-click installer (Velopack `Setup.exe`, per-user, no admin) and its update feed are built by `.github/workflows/windows.yml` on pushes to `windows-build` and on `v*` tags (tags also publish a GitHub Release). Installed Windows apps download newer releases in the background and install them when CrateMind closes (`native/src-tauri/src/updates.rs`; see the operations guide). The same workflow builds a Developer ID signed, notarized macOS arm64 DMG for every tag (signing secrets: see the operations guide).
- **Shared library:** the web runner can use the desktop dataset folder via `CRATEMIND_DATASET_ROOT`; a dataset lease then allows only one app at a time.

## Architecture

### Backend (`backend/app/`)
Layered: `api/` routers → `services/` logic → `models.py` (SQLModel) + `db.py` (engine, FTS, backup). Routers mount under `/api` in `main.py`/`app_factory.py`. `config.py` is env-driven (`pydantic-settings`, `CRATEMIND_*` vars, `lru_cache`d settings; look settings up per call, never bind them at import).

- **`db.py`:** SQLite in WAL mode. `init_db()` is idempotent (tables, pragmas, the `track_search` FTS5 table). `backup_on_launch()` snapshots the database at most once per rolling 24 hours, and always before a pending schema upgrade when the library lives in a dataset folder; it keeps `backup_keep` bundles (default 3; on desktop the `cratemind-backup-keep` preference, exactly "1" to "7", set in Settings and read at launch by `config._apply_desktop_backup_keep`). FTS is kept in sync manually via `reindex_track()` / `reindex_all()`: call these after any write that changes searchable columns.
- **`models.py`:** `Track` is the spine (`id` primary key, unique `absolute_path`); `quick_hash`/`full_hash`/Chromaprint `Fingerprint` give content identity. `TrackDJProfile` (1:1) holds the taste axes. Other tables: `Tag`/`TrackTag`, `DuplicateGroup(+Track)`, `DJSet`/`SetTrack`, `TrackPairNote` (transition memory), `PlayEvent`, `AuditLog`, `Job`, `SavedSearch` (Memory Crate), `track_cues`, `TrackBeatgrid` (one row per source: the djay import, and CrateMind's own detected grid), `TrackDownbeat` (user downbeat), `TrackStructure` (sections and phrase lines). Any schema change needs the regenerated schema contract.
- **`services/search.py`:** the search mini-language (`energy:7-9`, `status:approved`, `bpm:148-155`, `role:peak`, `-retired`, `not_recent:30`, …) compiles to SQLAlchemy criteria; bare words become FTS5 free text. To add a field, extend `_PROFILE_NUM` / `_TRACK_NUM` / `_STR_FIELDS` and the boolean-token handling, and keep `docs/README.md#search-syntax` in sync. `OR` joins a term to the next one; `sort:` and `limit:` are pulled out of the query before filtering and `limit:N` is applied inside `_build_query`, so every consumer (counts, saved searches, facets, bulk edit) sees at most N tracks. The Library sorts in the browser: with a known `sort:` token it keeps the server's order, and `SORT_FIELDS` in `frontend/src/lib/libraryExtras.ts` must mirror `_SORT_FIELDS`.
- **`services/recommender.py`:** a *transparent* weighted scorer (explicitly "not AI"): every candidate returns positive/negative reasons. Relative tempo fit, Camelot-wheel key compatibility, style (psy_substyle → artist genre → genre tag on a style ladder), a bridge mode aimed at the A–B midpoint, and `TrackPairNote` memory (low ratings penalise); `match` (0–100) is musical fit only. `POST /api/recommend` serves Flow Finder without a set. Re-measure with `.omc/research/recommender-eval` (the user's own sets as ground truth, on a backup copy) before changing weights.
- **`services/beatgrid_detect.py`:** CrateMind's own beat grid from the audio (NumPy only): tempo, beat position, bar line and a confidence; one steady grid, or a beat list of steady sections for a track with a timing jump or a tempo change. It runs as the last phase of `analyze_all` with its own track selection, so a backlog never re-runs BPM, key or providers. `GET /tracks/{id}/beatgrid` serves ours when confident, else djay's. A confident steady grid's tempo is also the track's BPM, second after a manual one (`tracks.bpm_grid`, resolved in `services/tempo.py` and `frontend/src/lib/tempo.ts`, which must stay in step). Method, measured accuracy and limits: `docs/BEATGRID_DETECTION.md`; re-measure before changing the method.
- **`services/key_detect.py`:** CrateMind's musical key from the whole track (librosa CQT, log-compressed 2-second blocks, 84 semitones with the octaves kept apart, scored with weights trained on tracks whose key two or three DJ apps agree on; the confidence is the key's probability). It runs in the first analysis pass, whose one whole-track decode also feeds the BPM (first 120 s), and in a key phase of `analyze_all` that re-keys tracks whose `tracks.key_analyzed_method` is older than `key_detect.METHOD`. A track's key is its file tag, then ours when its confidence is at least 0.7, then djay's key (`tracks.key_djay`, mirrored from the djay rows by `djay_import.sync_djay_keys`), then ours at any confidence: `services/musical_key.py` and `fallbackKey` in `frontend/src/lib/camelot.ts` must stay in step. Method, measured accuracy and limits: `docs/KEY_DETECTION.md`; re-measure with `.omc/research/key-eval` before changing it.
- **`services/track_structure.py`:** a track's sections (bass on/off) and phrase lines (every 8 bars from each beat where the sub-bass comes in), measured along CrateMind's own confident grid (NumPy only). It is computed in the grid phase of `analyze_all`, in the same decode (a track whose grid is current is only read for its structure), and stored in `track_structures`. `GET /tracks/{id}/structure` serves it to the Phrase Finder page; `GET /tracks/{id}/beatgrid` adds the phrase lines when it serves CrateMind's grid. With «Χρονισμός από τη δομή» on (`Prefs.transitionStructureTiming`, off by default), the frontend planner times unsaved transition windows from it (`frontend/src/lib/transitions/structurePlacement.ts`; with the switch off, plans must stay as `frontend/tests/transitionPlannerGolden.test.ts` pins them). A bass pause shorter than 12 beats between two bass runs is not a section and does not restart the phrase count, and an anchor one beat off the bar line counts from the bar line (method version 2). The structure is measured along the track's real tempo octave: a grid an octave off the resolved BPM is folded first (`tempo_factor`/`fold_beats`, the same fold `foldPeriod` in `frontend/src/lib/beatGrid.ts` makes on a steady grid) and the row's JSON records the tempo it was measured at (`bpm`); the only-new grid phase re-reads a structure whose recorded tempo no longer matches, so keep the two folds in step. The owner's hand cues and downbeats are not a reliable reference for this method: never tune it to them or quote agreement with them as accuracy. Method, measurements and limits: `docs/TRACK_STRUCTURE.md`; re-measure before changing the method.
- **`services/playback_loudness.py`:** a track's integrated LUFS and true peak (ffmpeg `ebur128`, read-only), stored on `tracks` (`loudness_*`). Measured in the last phase of `analyze_all` (its own selection: never measured) or on demand by Auto Gain's `GET /tracks/{id}/playback-loudness`; a rescan with a new duration clears it. It feeds the Library «LUFS» column and the `lufs:` search field.
- **`api/history.py`:** play history over `play_events` (`deck`, `ended_at`, `played_seconds` are set only for recorded plays; `played_at` is the start). `GET /history` pages newest first on `(julianday(played_at), id)` with a `before_id` keyset; recording a play bumps `play_count`/`last_played_at`, deleting plays lowers them again; save-as-set builds a `DJSet` in play order.
- **`api/deck_rescue.py`:** deck rescue, the decks' last state as one JSON file in the catalog's cache folder (`cache/deck-rescue.json`, replaced atomically; a file, not a table, so there is no schema change and nothing in backups or exchange bundles). GET answers null for a missing, unreadable, other-version or over-24-hour file and never deletes it; the page writes it and deletes it. `deck_playing()` reads the same file (fresh and both decks loaded) so that `analyze_all` waits between tracks while a two-deck set plays (`audio_analysis._after_decks`).
- **`services/djay_import.py`:** read-only djay Pro import (analysis format v8, 4/4). Copies `MediaLibrary.db` + `-wal` (never `-shm`) to a private temp dir, never opens the live DB, reads `.djayMetadata` plists in place.
- **`services/waveform_detail.py`:** CMWD v2 binary detail waveform (RMS/peak envelopes plus frequency RGB colours; NumPy only, no SciPy). `waveform_color.py` computes the colours and `waveform_density.py` renders the per-tile signed-PCM density texture.
- **`jobs/worker.py`:** a threaded runner over the `jobs` table (deliberately not Celery/RQ); each job gets its own `Session`. Poll progress via the `Job` row. A running analyze job is stopped through `POST /api/scan/analyze/{job_id}/stop`: the route touches `<plan file>.stop`, every `analyze_all` phase checks `audio_analysis.stop_requested()` between tracks (queued tracks are skipped, running ones finish and are kept) and the child is terminated after `worker.STOP_GRACE_S`. A new phase loop must iterate `_completed(futures)` and return early on `stop_requested()`. A forced run keeps a track's last BPM and key when its file cannot be decoded.
- **`services/relink.py` and the scan guard:** a root with at least 20 known tracks that would lose more than half of them in one scan marks none missing and ends with a Greek warning (`scanner.MASS_MISSING_NOTE`, read by `frontend/src/lib/relink.ts`); only `allow_mass_missing` on the scan request overrides it. `relink.py` proposes moved-and-retagged pairs (a missing row with user work and a present row without, same Chromaprint audio and duration) for «Μετακινημένα κομμάτια» on the Duplicates page; the merge runs only on the user's confirmation, through `scanner.merge_tracks`, never automatically.
- **`api/sets.py`:** `DELETE /api/sets/{id}` removes the set's `set_tracks` and `set_transitions` rows and empties `play_events.set_id` (the plays stay). A new table that references `sets.id` must be handled there too.
- Other single-purpose services: `scanner`, `metadata_reader` (mutagen), `ffprobe_reader`, `fingerprint`, `duplicate_detector` (exact hash, artist/title, and an audio pass through `fingerprint_match`: a NumPy Chromaprint decoder and same-recording match, thresholds measured in `.omc/research/duplicate-audit-2026-11-18`), `hashing`, `exporter_{m3u,csv,markdown}`, `backup`, `streaming`, `audit`, `audio_analysis` (BPM/key, run in a spawned child process; local-only on desktop).

### Frontend (`frontend/src/`)
React + react-router. `app/App.tsx` maps the routes to `pages/` (Dashboard, Library, Artists, Crates, Playlists, Tagging queue `/tag`, Set Builder `/sets`, Flow, Energy maps, Key harmony, Tag cloud, Phrase Finder, Duplicates, Settings, plus capability-gated collection pages). `lib/api.ts` is the single typed fetch wrapper (`req<T>`); `lib/types.ts` holds shared route-level types. Tailwind v4 via the Vite plugin (config in `src/index.css`). `components/ui/` is the glass design system; `components/layout/` is the shell and sidebar. Two-deck playback uses the Signalsmith Stretch WASM worklet (`lib/audio/stretchDeck.ts`); the deck waveform panels portal from `MiniPlayer` into `DeckViewSlot`. In two-deck mode each deck has an FX rack: one AudioWorklet node per deck (`lib/fxRack/`, own DSP) sits after the deck's fader and before the master bus, bound by `lib/fxRackHost.ts` (mounted through `useFxRack` in AppShell), which posts the beat clock from the engine's anchor and grid (`lib/fxRackClock.ts`); `lib/fxRack.ts` is its store. Every deck's playback graph feeds one master bus (`lib/audio/masterBus.ts`). Two-deck decks always get a graph. A single-deck `<audio>` element plays natively, outside the bus, until Auto Gain, the Limiter or the Maximizer has been on (the gate in `prepare()` in `lib/usePlaybackProcessing.ts`). After that it stays on the bus for the element's lifetime. Anything new on the bus must also join that gate, with one approved exception: the bus's own always-on safety limiter (`masterBus.ts`, the deck limiter's worklet at -1 dB, after the insert slot; it steps aside while the Maximizer is the insert and is skipped when the worklet cannot load) acts only on what is already on the bus and never moves a native single-deck play onto it. The Maximizer is its insert, driven by `lib/useMaximizer.ts`; its engine is private (see Versioning & Releases) and `lib/audio/maximizer.ts` holds only its contract and `MAXIMIZER_BUILT`, which gates every control. A set recording («Εγγραφή», `lib/recorder.ts`) hears the bus output through `addMasterTap` (taps survive `setDeckSink`; a recording and the experimental VST3 slots refuse each other) and streams numbered 24-bit WAV chunks to `api/recordings.py` / `services/recorder.py`, which only ever create new files in the export folder; it joins the gate by reading `recordingActive()` (not a hook dependency, so REC never re-routes a playing deck). Play history: `lib/usePlayHistory.ts` (mounted in AppShell) records a play once a track has been audible on a deck for 30 s, never while `/tag` is open (pure logic in `lib/playHistory.ts`), and `pages/PlayHistory.tsx` (`/history`) lists the sessions. Deck rescue: `lib/useDeckRescue.ts` (mounted in AppShell) saves the decks and the mixer every 2 s while they change, deletes the file when both decks are ejected, and on a start that finds a snapshot offers to bring the decks back paused (pure logic in `lib/deckRescue.ts`); the seek and the loop are applied on the deck's `loadedmetadata`, through `deckTransportOf`, with no edits in `MiniPlayer.tsx`. Quantize («Q» in the mixer strip, `Prefs.quantize`, off by default, two-deck only): `lib/quantize.ts` holds the pure snapping, `planLoop` takes the grid, and `MiniPlayer` routes every cue jump through `jumpToCue`; it acts only on a grid Sync would trust, and with the switch off loops, cues and the Sync lock must behave exactly as before. `MiniPlayer.tsx` is the riskiest file (high churn); check the change risk before editing it. «Σχετικά με το CrateMind» is the page's own window (`components/AboutDialog.tsx`, opened by the Mac menu's `cm:about` event, the command palette and Settings); when a package a user would recognise is added or dropped, update its `CREDITS` list, and keep personal names out of it.

Deck and mixer rules added on 2026-11-26 (each switch is off by default, and with it off the decks must behave exactly as before):

- **Sync folds an octave:** `planSync` in `lib/deckSync.ts` matches the locked deck's BPM at half or double when that is nearer the other deck's tempo; the lock keeps that fold for its life and `phaseShift`/`lockStep` count beats with it (the button shows «SYNC ÷2» / «SYNC ×2»). `frontend/tests/syncLockSim.ts` is the closed-loop lock simulation: measure with it before changing the lock's trim, deadband or re-snap thresholds.

They are never `track_cues` rows until «Κράτα ως cue» (`padKeep` in `lib/padActions.ts`), and the controller LED stays dark for them.
- **Master level meter** (`components/MasterMeter.tsx`, opened with `openMasterMeter` in `lib/audio/masterBus.ts`): it only listens to the bus, never creates the bus or the AudioContext (`existingPlaybackContext`), and its listening points exist only while the meter is shown. «LIM» lights when what reaches the safety limiter is above the -1 dBFS ceiling.

## Coding Style & Naming Conventions

Python: simple modules with focused service functions and FastAPI routers. Prefer `pathlib`, structured parsing, SQLModel models and explicit error handling. Keep side effects obvious, especially around scanning, exports and file access.

TypeScript React function components. Page components use PascalCase filenames, shared helpers use camelCase, and route-level data types belong in `frontend/src/lib/types.ts` unless they are local to one component.

All user-facing UI copy must be in Greek: labels, buttons, headings, tooltips, toasts, error messages and report text. Use English only when no Greek word is a good match, such as `beatgrid`, `downbeat`, `BPM`, `M3U8`, `tag` or `export`. Never show internal keys or English reason codes (`non_straight`, `missing`) to the user; map them to Greek text.

## Testing Guidelines

Backend: `pytest`, files named `test_*.py` in `backend/tests/`. Add tests for scanner idempotency, parser behaviour, duplicate safety, recommender scoring, exports, data-safety guarantees and API regressions; build fixtures by hand, never from personal data. Frontend: `bun test` for pure helpers in `frontend/tests/`, and `bun run build` for type/build validation.

### Output Distillation

- Prefer `repowise distill <cmd>` for noisy commands — test runs, builds, `git status`/`log`/`diff`, searches, file listings. It runs the command unchanged (exit code preserved) and prints a compact, errors-first rendering; every error line survives.
- Output may contain a marker like `[repowise#a1b2c3d4e5f6: 230 lines omitted (~6.1k tokens); restore: repowise expand a1b2c3d4e5f6]`. The omitted content is fully preserved — run `repowise expand <ref>` to retrieve it, or `repowise expand <ref> -q <regex>` for just the matching lines.
- Never re-run a command to see omitted output; expand the marker instead.
- For structure-level questions about a large indexed file ("what's in here", "which function handles X"), `get_context(["path"], include=["skeleton"])` returns the file with bodies elided — every signature plus the bodies of the most central symbols — at a fraction of the cost of a full Read.
